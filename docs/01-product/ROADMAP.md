# 版本规划 Roadmap

> 当前只承诺 Phase 1：API 自动化测试 MVP。后续阶段仅作为方向，不提前实现。

---

## Phase 1：API 测试最小闭环（当前）

目标：完成可用、可测、可追溯的 API 自动化测试闭环。

范围：

- 认证与用户角色。
- API 项目管理。
- 环境管理。
- 集合管理。
- API 用例管理。
- 变量替换。
- 规则断言。
- 手动执行。
- 平台内置报告。
- pytest API 测试。

完成标准：

- 测试工程师可以创建用例并执行。
- 失败结果可定位到请求、响应和断言。
- 核心数据落库可追溯。

---

## Phase 2：API 测试效率增强

目标：减少用例创建和维护成本。

候选能力：

- OpenAPI / Swagger 导入。
- 自动生成基础用例。
- 集合和用例复制。
- 批量启用/禁用。
- 有限并发执行。
- 报告趋势统计。
- JSON / HTML 报告导出。

进入条件：

- Phase 1 闭环稳定。
- 项目、环境、用例、执行、报告核心接口测试通过。

---

## Phase 3：工程集成

目标：让 API 测试融入研发流程。

候选能力：

- 定时任务。
- Webhook。
- CI/CD 结果回调。
- 企业微信 / 钉钉 / 邮件通知。
- Nginx 生产部署完善。
- Redis Token 黑名单和缓存。

进入条件：

- 测试执行和报告已有稳定数据模型。
- 团队确实需要自动触发和通知。

---

## Phase 4：智能化能力

目标：在 API 测试闭环稳定后提升智能化效率。

候选能力：

- AI 生成测试用例。
- AI 辅助生成断言。
- AI 分析失败原因。
- 基于历史结果的用例优化建议。

进入条件：

- 已积累足够项目、用例和执行数据。
- 已完成安全、权限和数据脱敏设计。

---

## 规划原则

1. 不跨阶段实现复杂能力。
2. 每个阶段必须能独立交付价值。
3. 后续阶段不得破坏 Phase 1 的数据模型和接口契约。
4. 新技术引入必须补充 ADR。
