# API 自动化测试平台 · 错误恢复（Recovery）体验设计

> 文档类型：错误恢复体验设计规范
> 适用范围：API 自动化测试平台所有错误场景（Run / Import / 删除 / 网络 / Token / 权限 / 404 / 500 / 校验 / 冲突 / 超时）
> 设计阶段：先设计，不涉及代码实现
> 配套：`PRD.md`、`INFORMATION_ARCHITECTURE.md`、`NavigationUX.md`、`Journey.md`、`WorkflowReview.md`、`FirstRunGuide.md`、`EmptyState.md`、`QuickAction.md`、`Feedback.md`
> **硬约束：不新增任何 API、不新增任何数据库表、不新增功能模块——仅复用已有 Ant Design 组件（Alert / Modal / Drawer / message / notification）+ 已有前端路由 + 已有 API 错误响应**

---

## 0. 设计目标

让用户在**任何错误场景下**都知道**下一步该做什么**，并能**1~2 次点击**恢复到正常流程。

**三大原则**：

1. **永远告诉用户下一步**：错误状态**必须**有"下一步"按钮 / 链接，不是死路。
2. **保留用户上下文**：错误发生后**不丢失用户已输入的数据**（表单不关 / 列表不刷新 / Tab 不切换）。
3. **错误可追溯**：错误码 + 错误信息**完整展示**，方便用户截图给运维 / 二次排查。

---

## 1. 错误分类与响应策略

### 1.1 错误级别分类

| 级别 | 含义 | 用户影响 | 反馈组件 |
|---|---|---|---|
| **Level 1**（轻） | 表单校验失败 / 输入不合法 | 用户必须修正才能继续 | 字段下方红字 + Toast |
| **Level 2**（中） | 单次操作失败（保存 / 删除 / 执行） | 该操作失败，其他不受影响 | Toast / Drawer 内 Alert + 重试按钮 |
| **Level 3**（重） | 页面级失败（资源 404 / 403 / 网络断开） | 当前页面无法继续 | ErrorState 整页组件 + 重试 / 返回按钮 |
| **Level 4**（危） | 会话级失败（Token 失效） | 整个 App 受影响 | 全局拦截 + 跳登录页 + returnTo |

### 1.2 通用恢复路径

```text
[错误发生]
   ↓
[显示反馈（Toast / Alert / ErrorState）]
   ↓
[提供"下一步"按钮]  ← 核心：永远告诉用户下一步
   ↓
[用户点击 → 恢复路径]
   ├─ 一键重试（重新发起失败的请求）
   ├─ 修正输入（聚焦到出错字段）
   ├─ 跳转上级（返回列表 / 返回 Dashboard）
   └─ 联系支持（提供错误码）
```

# 2. Run 失败恢复

## 2.1 错误分类

Run 失败分**两类**，恢复策略不同：

| 失败类型 | 含义 | 恢复策略 |
|---|---|---|
| **执行失败** | Run 本身无法启动（环境不可达 / 后端报错） | Drawer 内 Alert + 重试 + 改环境 |
| **测试失败** | Run 启动成功，但部分 Case failed / error | 不是 Run 失败，是 Case 失败 → 走 Result 详情 → 修复 |

## 2.2 执行失败（同步执行报错）

### 触发条件

- Run Drawer 提交后，`POST /runs` 返回非 2xx
- 后端响应超时（> 60s）
- 环境 Variables 引用未定义（如 `{{token}}` 未配置）
- 网络中断

### 错误信息

| 场景 | 文案 |
|---|---|
| 后端 500 | "执行失败：服务器内部错误（错误码 50001）" |
| 后端 400 | "执行失败：[后端 message]"（如"环境 Variables 缺失 token"） |
| 网络中断 | "执行失败：网络连接已断开" |
| 超时 | "执行超时：执行时间超过 60 秒，已自动取消" |

### 用户感知

```text
┌────────────────────────────────────────────────────┐
│  ✕ 执行失败                                [关闭]  │
│                                                    │
│  错误码：50001                                     │
│  错误信息：服务器内部错误，请稍后再试              │
│  Run 名称：用户服务回归 16:42                       │
│                                                    │
│  💡 你可以：                                       │
│  · 重新发起执行（推荐）                            │
│  · 切换到其他环境                                  │
│  · 查看 Run 历史报告                                │
│                                                    │
│  [🔄 重新执行] [🌐 切换环境] [📋 查看报告列表]    │
└────────────────────────────────────────────────────┘
```

**位置**：RunExecutionDrawer 顶部 Error Alert（Drawer **保留不关闭**）。

### 下一步操作

| 按钮 | 行为 | 适用场景 |
|---|---|---|
| **🔄 重新执行** | 保留所有原配置，立即重试 | 偶发性错误 |
| **🌐 切换环境** | 打开环境选择下拉 | 环境错误 |
| **📋 查看报告列表** | 关闭 Drawer，跳 Report 列表 | 想看历史 Run |
| **关闭** | 关闭 Drawer | 用户主动放弃 |

### 实现位置

`RunExecutionDrawer.tsx` 已有 `setError(...)` 逻辑，扩展为完整 Alert 组件。

## 2.3 测试失败（Run 启动成功，Case failed / error）

### 触发条件

- Run 状态 = finished，但 Result 中存在 failed / error

### 错误信息

- **不是 Run 失败**，而是 **Case 失败**
- Run 详情默认 Tab = **失败原因**（已实现）
- 每条失败项显示：Case 名 / Method / Path / 断言类型 / expected / actual / error_code

### 下一步操作（Run 详情）

```text
┌────────────────────────────────────────────────────┐
│  用户服务回归  92.5%  suite  12 Case  12.3s        │
│                                                    │
│  失败原因 Tab 默认展开                              │
│  · GET /users/1                                    │
│    Expected: 200  Actual: 500  Operator: eq        │
│    [🔧 修改此 Case] [▶️ 重新执行整个 Suite]        │
│  · POST /auth/login                                │
│    Expected: 200  Actual: 401  Operator: eq        │
│    [🔧 修改此 Case]                                │
└────────────────────────────────────────────────────┘
```

| 按钮 | 行为 | 节省 |
|---|---|---|
| **🔧 修改此 Case** | 1 步跳 Case Editor（带 `?from=report&runId=&resultId=`） | 节省 3 步 |
| **▶️ 重新执行整个 Suite** | 1 步打开 Drawer，预填原 scope | 节省 4 步 |

### 修复后重跑流程

```text
[Run 详情 → 失败项 → 修改 Case]
   ↓
[Case 编辑器修改 + 保存]
   ↓
[点击"💾 保存并执行" → 1 步打开 Drawer 预填]
   ↓
[Run Now → 新 Run 报告]
```

**节省**：原来 6 步（Run 详情 → 失败 Tab → Result 详情 → Case 列表 → Case 编辑器 → 执行）降至 **3 步**。

# 3. Import 失败恢复（OpenAPI Import）

## 3.1 错误分类

| 失败类型 | 触发 | 恢复策略 |
|---|---|---|
| **解析失败** | OpenAPI 文档格式错误 / 版本不支持 | Modal 保留 + 错误详情 + "换一个来源" |
| **预览失败** | `preview_id` 不可用 / 后端报错 | Modal 保留 + 重试 |
| **导入失败** | 用户确认后导入报错（冲突 / 网络） | Modal 保留 + 错误详情 + 调整策略重试 |

## 3.2 解析失败

### 错误信息

| 场景 | 文案 |
|---|---|
| 文档不是 JSON | "解析失败：文档不是合法的 JSON，请检查格式" |
| 版本不支持 | "解析失败：仅支持 OpenAPI 3.0 / 3.1，检测到 Swagger 2.0" |
| 缺少 paths | "解析失败：文档中没有定义任何 API operation" |
| 后端 500 | "解析失败：服务器内部错误（错误码 50002），请稍后重试" |

### 下一步操作

```text
┌────────────────────────────────────────────────────┐
│  ✕ 解析失败                              [关闭]    │
│                                                    │
│  错误码：50002                                     │
│  错误信息：仅支持 OpenAPI 3.0 / 3.1                │
│  检测到版本：Swagger 2.0                            │
│                                                    │
│  💡 你可以：                                       │
│  · 换一个 OpenAPI 来源                             │
│  · 用工具（Swagger Editor）转换 2.0 → 3.0         │
│                                                    │
│  [🔄 换一个来源] [📖 查看转换教程]                │
└────────────────────────────────────────────────────┘
```

## 3.3 导入失败

### 错误信息

| 场景 | 文案 |
|---|---|
| 冲突且 overwrite 失败 | "导入失败：overwrite 操作被后端拒绝" |
| Suite 不存在 | "导入失败：目标 Suite 不存在或已被删除" |
| 部分失败 | "导入部分失败：成功 5 条 / 失败 3 条 [查看失败详情]" |

### 下一步操作

| 按钮 | 行为 |
|---|---|
| **🔄 重试** | 重新发起导入（保留已填配置） |
| **⚙️ 切换冲突策略** | 改 skip / overwrite 后重试 |
| **📦 换一个 Suite** | 返回 Suite 选择 |
| **关闭** | 用户主动放弃 |

### 实现位置

`WorkspaceImport.tsx` 增加 ErrorState / Alert 组件，保留 Modal 不关闭。

# 4. 删除失败恢复

## 4.1 触发条件

- `DELETE` 接口返回非 2xx
- 资源被引用（外键约束，409 Conflict）
- 网络中断

## 4.2 错误信息

| 场景 | 文案 |
|---|---|
| 默认环境 | "删除失败：该环境是 Project 默认环境，请先设置其他环境为默认" |
| Suite 关联 Case | "删除失败：Suite 仍关联 X 条 Case，请先移除关联" |
| Project 关联资产 | "删除失败：Project 仍包含 Environment / Suite / Case" |
| 网络中断 | "删除失败：网络连接已断开" |
| 后端 500 | "删除失败：服务器内部错误（错误码 50003）" |

## 4.3 下一步操作

### Popconfirm 内嵌 Alert（已删除场景）

```text
┌────────────────────────────────────────────────────┐
│  ⚠️ 删除失败                              [关闭]  │
│                                                    │
│  错误码：40901                                     │
│  错误信息：该环境是 Project 默认环境                │
│                                                    │
│  💡 你可以：                                       │
│  · 先将其他环境设为默认，再删除该环境              │
│  · 取消删除                                        │
│                                                    │
│  [🌐 去设置默认环境] [取消]                       │
└────────────────────────────────────────────────────┘
```

| 按钮 | 行为 |
|---|---|
| **🌐 去设置默认环境** | 跳转 Environment 列表 |
| **取消** | 关闭 Popconfirm |

### 反例

- ❌ 删除失败后 Popconfirm 自动关闭（用户无法看到错误）
- ❌ 错误文案不具体（"删除失败"）
- ❌ 不提供"去设置默认环境"快捷按钮（用户必须自己找）

# 5. 网络异常恢复

## 5.1 错误分类

| 类型 | 触发 | 恢复策略 |
|---|---|---|
| **请求失败** | 后端不可达 / 网络断开 / DNS 失败 | Toast + 缓存数据保留 |
| **请求超时** | 请求 > 30s 未返回 | Toast 警告 + 后台继续 |
| **响应 5xx** | 后端服务异常 | Toast 错误 + 重试 |
| **响应 0 / CORS** | 跨域或后端宕机 | 全局错误页 + 重试 |

## 5.2 错误信息

| 场景 | 文案 |
|---|---|
| 网络断开 | "网络连接已断开，请检查网络后重试" |
| 请求超时 | "请求超时（30 秒），已在后台重试" |
| 500 服务器错误 | "服务器开小差了，请稍后再试（错误码 50000）" |
| CORS / 0 响应 | "无法连接到服务器，请检查后端服务状态" |

## 5.3 用户感知 + 下一步

### 单次请求失败（Mutation）

```text
┌────────────────────────────────────────────────────┐
│  ✕ 保存失败                              [关闭]    │
│                                                    │
│  网络连接已断开                                     │
│                                                    │
│  💡 你的输入已保留，重新连接后可继续保存            │
│                                                    │
│  [🔄 重试] [取消]                                  │
└────────────────────────────────────────────────────┘
```

**位置**：Drawer / Modal 内顶部 Alert（**不关闭**，保留用户输入）。

### 列表 / 详情请求失败

```text
┌────────────────────────────────────────────────────┐
│              ⚠                                    │
│                                                    │
│       无法加载 [对象列表]                          │
│       网络连接已断开                                │
│                                                    │
│       [🔄 重新加载] [← 返回 Dashboard]            │
│                                                    │
└────────────────────────────────────────────────────┘
```

**位置**：ErrorState 整页组件。

### 全局网络断开（多次请求失败）

```text
┌────────────────────────────────────────────────────┐
│  ⚠️ 网络连接已断开                                  │
│  平台将在网络恢复后自动重试                          │
│  [手动重试]                                        │
└────────────────────────────────────────────────────┘
```

**位置**：屏幕底部全局 Banner（持续可见），网络恢复后自动消失。

## 5.4 下一步操作汇总

| 场景 | 按钮 |
|---|---|
| 单次请求失败 | 重试 / 取消 |
| 列表 / 详情请求失败 | 重新加载 / 返回 Dashboard |
| 全局网络断开 | 手动重试 |
| 请求超时 | Toast 警告 + 后台继续 |

### 反例

- ❌ 网络错误时清空用户输入（丢失数据）
- ❌ 网络错误只显示"网络错误"+ OK（用户无法重试）
- ❌ 多次失败后不显示全局 Banner（用户不知整个 App 受影响）

# 6. Token 失效恢复

## 6.1 触发条件

- API 返回 401 Unauthorized
- Token 过期（前端解码 JWT 发现 exp 过期）
- 用户被管理员禁用

## 6.2 错误分类

| 触发 | 恢复策略 |
|---|---|
| Refresh Token 成功 | 静默重试原请求，用户无感 |
| Refresh Token 失败 | 跳登录页 + returnTo |
| 用户被禁用 | 跳登录页 + 文案"账号已禁用，请联系管理员" |

## 6.3 用户感知 + 下一步

### Refresh 成功（无感）

用户**完全无感**，原请求自动重试并完成。

### Refresh 失败（需重新登录）

```text
┌────────────────────────────────────────────────────┐
│  ⚠️ 登录已过期                                      │
│                                                    │
│  请重新登录以继续工作                               │
│                                                    │
│  💡 登录后将自动回到原页面                          │
│                                                    │
│  [🔑 去登录]                                       │
└────────────────────────────────────────────────────┘
```

**位置**：Notification（右上角）+ 1 秒后自动跳 `/login?returnTo=...`。

**sessionStorage["app.returnTo"]** 保存原 URL，登录成功后自动跳回。

### 用户被禁用

```text
┌────────────────────────────────────────────────────┐
│  ⚠️ 账号已禁用                                      │
│                                                    │
│  您的账号已被管理员禁用                              │
│  如需恢复，请联系平台管理员                          │
│                                                    │
│  [🔑 重新登录]                                     │
└────────────────────────────────────────────────────┘
```

## 6.4 下一步操作

| 场景 | 按钮 |
|---|---|
| Refresh 失败 | 跳登录页 + returnTo |
| 用户被禁用 | 跳登录页 + 文案提示 |

### 反例

- ❌ Token 失效后立即跳登录页（不尝试 Refresh）
- ❌ 跳登录页后丢失原 URL（用户需重新导航）
- ❌ 用户被禁用时不说明原因（用户不知所措）

### 实现位置

`frontend/src/api/client.ts` 的 axios 拦截器 + `frontend/src/components/RouteGuards.tsx`。

# 7. 权限不足恢复（403 Forbidden）

## 7.1 触发条件

- API 返回 403
- 路由守卫检测到当前用户角色不足
- 资源 owner 不是当前用户

## 7.2 错误信息

| 场景 | 文案 |
|---|---|
| 未登录 | "请先登录后再访问此页面" |
| 角色不足 | "无权限访问此页面，需要 [所需角色] 权限" |
| 资源 owner 变更 | "你已不是 Project [name] 的成员" |
| 项目被禁用 | "该 Project 已被禁用" |

## 7.3 用户感知 + 下一步

### 路由级 403（用户访问受限路由）

```text
┌────────────────────────────────────────────────────┐
│                  🔒                                │
│                                                    │
│              无权限访问此页面                       │
│       需要管理员权限才能访问用户管理                 │
│                                                    │
│  💡 如需访问，请联系平台管理员申请权限              │
│                                                    │
│       [← 返回 Dashboard]                           │
│                                                    │
└────────────────────────────────────────────────────┘
```

**位置**：`/403` 错误页。

### 资源级 403（用户访问不属于自己的资源）

```text
┌────────────────────────────────────────────────────┐
│  ⚠️ 你已不是 Project X 的成员                       │
│                                                    │
│  你可能已被移除，或 Project 已被删除                │
│                                                    │
│  [← 返回项目列表]                                  │
└────────────────────────────────────────────────────┘
```

**位置**：项目工作区顶部 Alert（持续可见）+ 跳 Dashboard。

### 操作级 403（用户尝试越权操作）

```text
┌────────────────────────────────────────────────────┐
│  ✕ 操作失败                              [关闭]    │
│                                                    │
│  你没有删除 Suite 的权限                            │
│  错误码：40301                                     │
│                                                    │
│  💡 你可以：                                       │
│  · 联系 Project owner 申请权限                     │
│  · 取消操作                                        │
│                                                    │
│  [取消]                                            │
└────────────────────────────────────────────────────┘
```

**位置**：Drawer / Modal 内 Alert。

## 7.4 下一步操作

| 场景 | 按钮 |
|---|---|
| 路由级 403 | 返回 Dashboard / 申请权限（联系管理员） |
| 资源级 403 | 返回项目列表 / 联系管理员 |
| 操作级 403 | 取消 / 联系 Project owner |

### 反例

- ❌ 403 时只显示"无权限"+ OK（用户不知如何获得权限）
- ❌ 操作级 403 不区分"路由级 / 资源级 / 操作级"
- ❌ 不告诉用户该找谁申请权限

# 8. 资源不存在恢复（404 Not Found）

## 8.1 触发条件

- API 返回 404
- 资源已被删除
- URL 中的 ID 错误

## 8.2 错误信息

# 13. 全局错误处理机制

## 13.1 Axios 拦截器统一处理

```typescript
// frontend/src/api/client.ts
axios.interceptors.response.use(
  response => response,
  error => {
    const status = error.response?.status;
    const requestId = error.response?.headers['x-request-id'];

    switch (status) {
      case 401:
        // 尝试 Refresh Token，失败则跳登录
        return handle401(error);
      case 403:
        return Promise.reject(formatError(error, '权限不足'));
      case 404:
        return Promise.reject(formatError(error, '资源不存在'));
      case 409:
        return Promise.reject(formatError(error, '操作冲突'));
      case 422:
        return Promise.reject(formatError(error, '字段校验失败'));
      case 500:
      case 502:
      case 503:
      case 504:
        return Promise.reject(formatError(error, '服务器错误'));
      default:
        if (!error.response) {
          // 网络断开 / CORS / 超时
          return Promise.reject(formatError(error, '网络异常'));
        }
        return Promise.reject(error);
    }
  }
);
```

## 13.2 全局错误监听

```typescript
// frontend/src/main.tsx
window.addEventListener('unhandledrejection', (event) => {
  // 全局兜底：未捕获的 Promise 错误
  notification.error({
    message: '系统异常',
    description: event.reason?.message || '请刷新页面或联系管理员',
  });
});
```

## 13.3 错误信息格式化

所有错误展示必须包含：

| 字段 | 来源 | 示例 |
|---|---|---|
| **错误码** | 后端 `code` 字段 | "50001" |
| **错误信息** | 后端 `message` 字段 | "服务器内部错误" |
| **请求 ID** | 后端 `x-request-id` Header | "req-abc123" |
| **时间戳** | 前端生成 | "2026-07-16 16:42:30" |

**企业级要求**：错误码 + 请求 ID 是排查问题的核心线索，必须暴露给用户。

# 14. 错误恢复的通用规则

## 14.1 三大铁律

1. **永远告诉用户下一步**：每个错误状态**必须**有"重试 / 返回 / 取消"按钮之一
2. **保留用户输入**：表单 / Drawer / Modal 失败时**不关闭**，保留用户输入
3. **暴露错误细节**：错误码 + 请求 ID 必填，方便企业级排查

## 14.2 错误信息结构

每个错误信息包含：

```text
[主标题]（一行简短）
[详细描述]（解释发生了什么）
[错误码 + 请求 ID]（用于排查）

[下一步建议]（告诉用户该怎么办）
[操作按钮]（重试 / 返回 / 取消 / 联系支持）
```

## 14.3 按钮分级

| 优先级 | 按钮 | 颜色 |
|:-:|---|---|
| **P0 主操作** | 重试 / 打开已存在 / 去设置 | Primary 蓝 |
| **P1 次操作** | 返回列表 / 取消 | Default 灰 |
| **P2 危险** | 强制删除 / 联系支持 | Link 蓝 |

## 14.4 错误兜底（无具体错误信息）

若后端未返回具体信息：

- ❌ 不要说"未知错误" / "出错了"
- ✅ 说"操作失败，请稍后重试（错误码：50000）"
- ✅ 提供"联系管理员"按钮（含 request_id）
