# API 自动化测试平台 · Empty State 设计规范

> 文档类型：产品 Empty State 设计规范
> 适用范围：API 自动化测试平台所有页面
> 设计阶段：先设计，不涉及代码实现
> 配套：`PRD.md`、`INFORMATION_ARCHITECTURE.md`、`NavigationUX.md`、`Journey.md`、`WorkflowReview.md`、`FirstRunGuide.md`
> **核心原则：不显示"No Data"。每个空态都必须告诉用户「下一步应该做什么」。**

---

## 0. 设计原则

### 0.1 三大铁律

1. **不显示 "No Data / 暂无数据"** —— 这是反例。所有空态必须用一句话告诉用户：**为什么空 + 下一步做什么**。
2. **每个空态必须有主操作按钮** —— 按钮直接**打开对应 Drawer / 跳转到对应页面**，**绝不只显示文字**。让用户**1 次点击**就能走出空态。
3. **每个空态必须有"退出条件"** —— 明确什么数据出现后该空态自动消失，避免长期停留。

### 0.2 四元素结构（每个空态必须包含）

```text
┌──────────────────────────────────────────────────────────────────────┐
│                                                                       │
│                          [图标 / 插画]                                │
│                                                                       │
│                  一句话标题（≤ 15 字，动宾结构）                      │
│                                                                       │
│            一句话副标题（解释「为什么空」+「该做什么」）               │
│                                                                       │
│                  [主操作按钮] [次操作按钮]                            │
│                                                                       │
│                       💡 一句话小贴士                                 │
│                                                                       │
└──────────────────────────────────────────────────────────────────────┘
```

| 元素 | 长度 | 目的 | 反例 |
|---|---|---|---|
| **图标 / 插画** | 1 个 | 视觉锚点，避免纯文字冰冷感 | 多图标 / 复杂插画 |
| **标题** | ≤ 15 字 | 用**动宾结构**告诉用户"做什么" | "暂无数据" / "空空如也" |
| **副标题** | 1 句话（≤ 40 字） | 解释**为什么空** + **该做什么** | 仅"暂无数据" |
| **主操作按钮** | 1 个 | 1 步走出空态（打开 Drawer / 跳转） | 只显示链接 / 无按钮 |
| **次操作按钮** | 0~1 个 | 备选路径（"了解更多" / "跳过"） | 多于 2 个按钮 |
| **小贴士** | 1 句话（≤ 30 字） | 解释概念或最佳实践 | 长篇文档链接 |

### 0.3 退出条件分类

| 退出类型 | 含义 | 示例 |
|---|---|---|
| **资产创建退出** | 用户完成创建后该空态自动消失 | 创建 Project 后 Dashboard 空态消失 |
| **资产变化退出** | 用户通过其他路径产生数据后空态消失 | 手动建 Suite 后 Case 列表空态变为"该 Suite 无 Case" |
| **筛选重置退出** | 用户清除搜索 / 筛选条件后空态消失 | 清空搜索框，"搜索无结果"空态消失 |
| **永不退出** | 空态持续显示直到主操作完成 | Dashboard 无 Project 一直显示直到首个 Project 创建 |

### 0.4 与 FirstRunGuide 的关系

- 用户处于**首次引导状态**（`app.firstRun.active === true`）时，**空态卡片不显示**，由 FirstRunGuide 的引导卡 + 自动 Drawer 接管。
- 用户**关闭引导 / 跳过引导**后，**空态卡片接管**继续引导用户完成剩余步骤。
- 二者**视觉上区分**：FirstRunGuide 使用 🎯 蓝色横幅 + 进度条；Empty State 使用 📦 中性卡片 + 主操作按钮。

## 1.3 Workspace Overview `/projects/:projectId/workspace/overview`

> Overview 的核心是"配置完整度 + 质量摘要 + 最近活动"。空态分**两类**：
> - **资产缺失空态**（按优先级显示一个）+ **最近活动空态**（Recent Runs 空）。

### 1.3.1 主空态 · 资产配置不完整（按缺失优先级）

**触发条件**：Environment / Suite / Case 任一为 0

**展示逻辑**（只显示**优先级最高**的一项）：

| 缺失 | 标题 | 副标题 | 主操作 |
|---|---|---|---|
| **0 Environment** | 配置你的测试环境 | 创建 Base URL、Headers、Variables 后才能发起 Run | 🌐 创建环境（打开 EnvironmentFormModal） |
| **0 Suite** | 创建测试套件 | 把 API 用例按业务场景组织到 Suite 中 | 📦 创建 Suite（打开 SuiteFormModal） |
| **0 Case** | 添加 API 用例 | 通过 OpenAPI 导入 或 手工创建 来生成 Case | 📥 导入 OpenAPI（跳 Import 页）/ ➕ 新建 Case（打开 Case Editor） |
| **三个都缺失** | 开始配置你的 Project | 先创建环境，然后导入或新建 API 用例 | 🌐 创建环境（**优先级最高**） |

**展示内容**（以 0 Environment 为例）：

```text
┌──────────────────────────────────────────────────────────────────────┐
│  项目摘要 · 用户服务 API                                              │
│  ─────────────────────────────                                       │
│                                                                       │
│                          🌐                                            │
│                                                                       │
│                    配置你的测试环境                                    │
│        创建 Base URL、Headers、Variables 后才能发起 Run                │
│                                                                       │
│                  [🌐 创建环境]                                        │
│                                                                       │
│            💡 第一个环境将自动设为默认环境                              │
│                                                                       │
└──────────────────────────────────────────────────────────────────────┘
```

**退出条件**：对应的缺失资产被创建 → Overview 自动 re-render 切换到下一个优先级空态或显示完整摘要。

# 2. Empty State 设计规范

## 2.1 视觉规范

| 属性 | 规则 |
|---|---|
| **图标** | Emoji（统一风格）或空状态插画，单色背景 |
| **标题字号** | 18px / Bold |
| **副标题字号** | 14px / Regular / 次要色 |
| **主按钮** | Primary 按钮，1 个 |
| **次按钮** | Default / Link 按钮，0~2 个 |
| **小贴士字号** | 12px / 次要色 |
| **垂直居中** | 上下 padding ≥ 64px，左右 padding 24px |
| **卡片背景** | 透明 / 浅灰背景，**不与 EmptyState 外层卡片冲突** |
| **最大宽度** | 480px（避免在宽屏拉得过宽） |

## 2.2 文案规范

| 规则 | 正例 | 反例 |
|---|---|---|
| **标题用动宾结构** | 创建你的第一个 Project / 添加 API 用例 | 暂无数据 / 空空如也 / 暂无 Project |
| **副标题解释"为什么空"** | 创建 Project 来组织你的 API 测试资产 | 请添加数据 |
| **主操作动词明确** | 📁 创建 Project | 确定 / 点击这里 |
| **小贴士给知识而非抱怨** | 建议按"服务名"创建 Project，例如"用户服务 API" | 这里什么都没有，快创建吧 |
| **避免技术术语** | Suite 是用例的分组 | Collection 是 test_case_ids 的关联关系 |
| **数字明确** | 5 个常见命名示例 | 一些常见命名 |

## 2.3 行为规范

| 规则 | 说明 |
|---|---|
| **空态可关闭** | 除 Dashboard / Overview 主空态外，允许用户关闭 |
| **空态不弹 Toast** | 空态本身不弹 Toast，仅主操作执行后弹 Toast |
| **空态不阻塞 Sider** | Sider 始终可切换模块，空态只影响当前页内容区 |
| **空态响应资产变化** | 任意空态在对应资产创建后立即消失（通过 React Query invalidate） |
| **空态响应筛选变化** | 搜索 / 筛选条件清空后，"搜索无结果"空态立即消失 |
| **空态不抢占 FirstRunGuide** | 引导状态下空态不显示，避免冲突 |

## 2.4 与 FirstRunGuide 协同

| 场景 | Empty State | FirstRunGuide |
|---|---|---|
| 用户首次登录，0 资产 | **不显示**（被 FirstRunGuide 引导卡 + 自动 Drawer 替代） | 显示 🎯 引导卡 + 自动 Drawer |
| 用户关闭引导，资产仍缺失 | **显示** Empty State（带主操作按钮） | 不显示（已 dismiss） |
| 用户在引导中，资产已部分创建 | 不显示 | 显示对应步骤的引导卡 |
| 引导完成后用户回到 Overview | 不显示 | 不显示（completed） |
| 用户在引导中但搜索无结果 | 显示"搜索无结果"空态 | 不影响（引导卡仍在顶部） |

# 5. 不在范围（防止范围蔓延）

- ❌ 空态插画 / 动画视频（避免引入新资源）

- ❌ 空态个性化（基于用户角色 / 历史），保持通用
- ❌ 空态 A/B 测试框架（需后端配合）
- ❌ 空态中的"创建示例数据"按钮（需后端新增 Seed API）
- ❌ 空态中的"导入模板"（需后端模板库）
