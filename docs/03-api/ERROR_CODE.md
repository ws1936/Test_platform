# 错误码规范

> 所有 API 错误响应必须使用统一结构，便于前端展示和测试断言。

---

## 1. 错误响应格式

```json
{
  "code": 10001,
  "message": "Project Not Found",
  "data": null
}
```

字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | 平台业务错误码 |
| `message` | string | 可读错误信息 |
| `data` | object/null | 错误附加信息，默认 null |

---

## 2. HTTP 状态码

| HTTP | 说明 |
|------|------|
| 200 | 成功 |
| 201 | 创建成功 |
| 204 | 删除成功，无响应体 |
| 400 | 请求语义错误 |
| 401 | 未认证或 Token 无效 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 资源冲突 |
| 422 | 参数校验失败 |
| 500 | 服务端异常 |

---

## 3. 通用错误码

| code | HTTP | 说明 |
|------|------|------|
| 0 | 2xx | 成功 |
| 10000 | 400 | 通用请求错误 |
| 11001 | 401 | 未登录 |
| 11002 | 401 | Token 无效或过期 |
| 11003 | 403 | 权限不足 |
| 12001 | 409 | 资源已存在 |
| 13001 | 422 | 参数校验失败 |
| 99999 | 500 | 系统内部错误 |

## 4. 认证与用户错误码

| HTTP | 业务 code |  说明 |
|------|------|------|
| 401 | `INVALID_CREDENTIALS` | 用户名或密码错误（20001，登录接口统一返回同一业务码以防枚举） |
| 403 | `ACCOUNT_DISABLED` | 用户已禁用（20002） |
| 409 | `USERNAME_TAKEN` | 用户名已存在（20003） |
| 409 | `EMAIL_TAKEN` | 邮箱已存在（20004） |
| 404 | `USER_NOT_FOUND` | 用户不存在（20005） |
| 400 | `INCORRECT_OLD_PASSWORD` | 旧密码错误（20006） |
| 401 | `TOKEN_INVALID` | Token 无效/过期/已吊销/版本过期（11002） |
| 403 | `FORBIDDEN` | 操作被拒绝（含“需超级管理员鉴权”） |
| 429 | `TOO_MANY_REQUESTS` | 限流/登录锁定 |
| 404 | `ROLE_NOT_FOUND` | 角色不存在（21001） |
| 409 | `ROLE_EXISTS` | 角色已存在（21002） |
| 400 | `ROLE_SYSTEM_IMMUTABLE` | 系统角色不可删除（21003） |

### 5.1 F012 OpenAPI 导入（复用 400）

F012 未引入新的整型错误码，所有导入异常统一映射到 HTTP 400，
具体语义由响应体的字符串 `code` 字段区分：

| HTTP | 业务 code | 说明 |
|------|-----------|------|
| 400 | `OPENAPI_PARSE_ERROR` | OpenAPI 文档无效 / 版本不支持（仅支持 3.0/3.1） |
| 400 | `OPENAPI_FETCH_ERROR` | URL 抓取失败（非 http/https、超时、4xx/5xx、非 JSON） |
| 400 | `OPENAPI_IMPORT_CONFLICT` | preview_id 失效 / 缓存丢失，需要重新预览 |
| 400 | `VALIDATION_ERROR` | 请求体不合法（`source_url` 与 `source_content` 必须二选一 / URL scheme 非法） |
| 400 | `OPENAPI_BATCH_LIMIT_EXCEEDED` | F013 批量：文档数 > `OPENAPI_BATCH_MAX_DOCS` 或 单文档 operation > `OPENAPI_BATCH_MAX_OPS_PER_DOC` |

设计依据：F012 属于客户端可控的输入校验，不属于系统/资源错误；
为避免错误码表膨胀，统一用 400 + 字符串 code 区分。

---

## 6. 使用原则

1. HTTP 状态码表达通用语义。
2. `code` 表达平台业务原因。
3. `message` 应清晰但不泄露敏感信息。
4. 登录失败不要暴露用户是否存在。
5. 执行异常应保存到 `api_test_results.error_message`，但日志需脱敏。
